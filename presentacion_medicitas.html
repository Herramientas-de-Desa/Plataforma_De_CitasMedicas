01

¿Cuál es el problema?

En muchas ciudades del Perú, y especialmente en Ica, conseguir una cita médica sigue siendo un proceso lento y tedioso. Los pacientes tienen que llamar por teléfono a varias clínicas, preguntar qué especialistas están disponibles, averiguar los horarios y, muchas veces, acercarse en persona solo para apartar un turno.

Esto genera varios problemas concretos:

  • Pérdida de tiempo tanto para el paciente como para el personal administrativo de la clínica.
  • Falta de información centralizada: no existe un solo lugar donde comparar especialistas, ubicaciones y horarios.
  • Doble reserva y desorganización cuando los registros se llevan de forma manual o en cuadernos.
  • Dificultad para encontrar la clínica más cercana, sobre todo para personas que no conocen bien la ciudad.
02

¿Qué es MediCitas?

MediCitas es una plataforma web que le permite a cualquier persona buscar médicos por especialidad, ver sus horarios en tiempo real y reservar una cita desde la comodidad de su celular o computadora, sin necesidad de hacer llamadas ni desplazarse.

Pero no se queda solo en la reserva. La plataforma también integra un mapa interactivo que detecta la ubicación del usuario y le muestra qué clínicas tiene más cerca, ordenadas por distancia. De esta forma, el paciente puede tomar una decisión informada: no solo elige al especialista que necesita, sino que también considera cuál le queda más conveniente geográficamente.

Además, el sistema contempla tres roles distintos — paciente, médico y administrador — lo que permite que cada actor del proceso de salud tenga su propio panel con las herramientas que necesita.

03

Objetivos del proyecto

Objetivo general

Desarrollar una plataforma web funcional que simplifique y agilice el proceso de búsqueda, recomendación y reserva de citas médicas en centros de salud de la ciudad de Ica, integrando geolocalización y gestión de horarios en tiempo real.

Objetivos específicos

  • Implementar un sistema de registro e inicio de sesión seguro con autenticación JWT y cifrado de contraseñas.
  • Construir un buscador que permita filtrar médicos por especialidad y nombre, mostrando solo profesionales disponibles.
  • Integrar un mapa interactivo con la ubicación GPS del usuario para recomendar las clínicas más cercanas.
  • Desarrollar un módulo de reservas que valide horarios y prevenga la doble asignación de turnos.
  • Ofrecer paneles diferenciados para pacientes, médicos y administradores del sistema.
04

¿Para quién está diseñado?

👤

Paciente

Cualquier persona que necesite atención médica. Puede registrarse, buscar especialistas, ver las clínicas en el mapa, reservar citas y llevar un historial de todas sus consultas desde un solo lugar.

🩺

Médico

El profesional de salud accede a su propia agenda, ve la lista de pacientes que tienen cita con él, puede confirmar la asistencia y marcar una consulta como atendida una vez que termina.

⚙️

Administrador

Tiene control total sobre el sistema: gestiona usuarios y sus roles, registra nuevos médicos, administra el catálogo de especialidades y supervisa todas las citas de la plataforma.

05

Funcionalidades principales

🔐

Registro y autenticación segura

Cuentas protegidas con tokens JWT y contraseñas cifradas automáticamente. Cada sesión es validada en cada acción.

🔍

Búsqueda inteligente de especialistas

Filtra por especialidad médica o escribe el nombre del doctor. Solo se muestran médicos que están disponibles y activos.

📅

Reserva de citas en tiempo real

El sistema cruza los horarios del médico con las citas ya ocupadas y muestra únicamente las horas libres, en bloques de 30 minutos.

🗺️

Mapa y geolocalización

Mapa interactivo con OpenStreetMap. Detecta tu ubicación por GPS y ordena las clínicas de la más cercana a la más lejana usando la fórmula de Haversine.

📋

Historial y gestión de citas

Los pacientes ven todas sus citas con estados claros (pendiente, confirmada, atendida, cancelada) y pueden cancelar si lo necesitan.

🛡️

Panel de administración completo

Gestión centralizada de usuarios, médicos, especialidades y supervisión de todas las citas del sistema desde un solo lugar.

08

Arquitectura del sistema

El proyecto sigue una arquitectura de tres capas bien separadas, lo que facilita el mantenimiento y la escalabilidad:

📱 Interfaz (UI) 13 componentes React organizados por funcionalidad: formularios, buscadores, paneles, mapa. Cada componente maneja su propia vista y estado local.
▼
🔧 Servicios 7 módulos JavaScript que encapsulan toda la lógica de acceso a datos: autenticación, médicos, citas, clínicas, especialidades, usuarios y geolocalización.
▼
☁️ Backend (API) Supabase genera automáticamente una API REST sobre la base de datos. La autenticación emite y valida tokens JWT en cada solicitud.
▼
💾 Base de Datos PostgreSQL con 6 tablas, 1 vista, triggers automáticos y políticas de seguridad por fila (RLS) que controlan el acceso según el rol del usuario.
09

Modelo de base de datos

Tabla Descripción Campos principales
usuarios Perfiles vinculados a la autenticación id, nombres, correo, teléfono, rol
especialidades Catálogo de áreas médicas id, nombre (único)
clinicas Centros de salud con ubicación GPS id, nombre, dirección, latitud, longitud
medicos Profesionales asignados a clínica y especialidad id, nombre, especialidad, clínica, disponible
horarios Disponibilidad semanal de cada médico médico, día de semana, hora inicio, hora fin
citas Reservas con protección contra duplicados paciente, médico, fecha, hora, estado

Además, el sistema incluye una vista desnormalizada llamada historial_citas que combina todas las tablas para consultas rápidas, y un trigger automático que crea el perfil del usuario en el momento del registro.

Seguridad del sistema

La seguridad no se trató como algo secundario, sino como un pilar del diseño desde el inicio:

🔑

Contraseñas cifradas

Supabase Auth aplica hash criptográfico a todas las contraseñas antes de almacenarlas. En ningún momento se guardan en texto plano.

🎫

Tokens JWT

Cada sesión activa se valida con un token JSON Web Token. Si el token expira o es inválido, se cierra el acceso automáticamente.

🚧

Row Level Security (RLS)

Cada tabla tiene políticas que verifican, a nivel de base de datos, que el usuario solo puede ver y modificar lo que su rol le permite.

🛤️

Rutas protegidas

En el frontend, un componente wrapper verifica la autenticación y el rol antes de permitir el acceso a cualquier página restringida.

14

Conclusiones

MediCitas demuestra que con las herramientas adecuadas es posible construir una solución real a un problema cotidiano. No se trata de un ejercicio teórico: es una plataforma funcional que resuelve la desorganización en la gestión de citas médicas y le devuelve al paciente el control sobre su propia salud.

A lo largo del desarrollo aprendimos a integrar múltiples APIs y servicios externos de forma coherente, a diseñar una base de datos relacional con seguridad incorporada desde el esquema, y a estructurar un proyecto frontend de manera que cada pieza — componente, servicio, contexto — tenga una responsabilidad clara.

El resultado es un sistema que no solo cumple con los requerimientos del curso, sino que podría adaptarse y desplegarse en un entorno real con ajustes mínimos. Esa fue siempre la intención: que lo que construimos sirva para algo más que una nota.
